# 03 — UI (`ui`)

**Archivos:** `app/components/**`, `app/lib/{site,motion,pipeline-state,pipeline-progress,stage-logs,tags}.ts`

> Para etapas, la línea, los nodos, los logs o el badge, usar la skill **`pipeline-page`**.

## Estructura

| Carpeta | Componentes |
|---------|-------------|
| `pipeline/` | `Stage` (sección = etapa), `StageNode`, `StageLog`, `Spine`, `PipelineBadge`, `StackPlayground` |
| `sections/` | contenido de cada etapa: `Checkout`, `Install`, `Build`, `Test`, `Release`, `Deploy` (+ `ContactForm`, `CopyButton`) |
| `ui/` | `ButtonLink` (pill blanca / contorno), `TechTag` (logo + nombre), `icons.tsx` |
| `layout/` | `IntroScreen`, `ScrollChoreography` (revelados + Lenis), `SiteHeader` (`~/matias-speroni`, badge del pipeline, links, CV), `SiteFooter` |

## Recorrido (`app/data/pipeline.ts` → `STAGES`)

| Etapa | Sección | Contenido | Log (de los datos) |
|-------|---------|-----------|--------------------|
| 01 checkout | `#top` | nombre (h1), rol, intro, disponibilidad, CTAs, highlights | `git clone …` · nombre y rol |
| 02 install | `#stack` | chips con logo por grupo + caja con física | N grupos, N tecnologías |
| 03 build | `#projects` | "artifacts": captura, built/building, tech con logos, links | N proyectos · shipped · en desarrollo |
| 04 test | `#experience` | "suites" por empresa con logros ✓ y etiquetas detectadas; certificaciones como checks | empresas · roles · desde · certificaciones |
| 05 release | `#about` | foto, bio, facts, educación | facts · párrafos |
| 06 deploy | `#contact` | canales, copiar email, formulario "Approve the deploy" | disponibilidad · "waiting for approval" |

## Contratos

- `NAV_ITEMS` = stack, projects, experience, about, contact (las etapas después de checkout).
- Secciones con `data-stage` (las pone `<Stage>`). Test ids: `node-<id>` (con `data-state`), `log-<id>`, `pipeline-badge`, `stack-playground`, `intro`, `build-info`.
- Layout en `page.tsx`: contenedor `relative`, padding izquierdo para la línea (`pl-14` / `sm:pl-24`); los nodos se ubican con offset negativo sobre la línea.

## Accesibilidad (axe con y sin reduced motion, después de recorrer la página)

- Un solo h1.
- Nodos con texto `sr-only` del estado.
- Línea, job y logs `aria-hidden`.
- Botones llenos en `accent-strong`.

## Rendimiento

Un solo listener de scroll pasivo (rAF) para todo el estado. matter-js se carga solo al ver la caja.
GSAP y Lenis son chunks dinámicos. Sin video ni 3D.

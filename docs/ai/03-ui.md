# 03 — UI (`ui`)

**Archivos:** `app/components/**`, `app/lib/{site,motion,deploy,site-config,config-init}.ts`

> Para Deploy, el editor de config o la física, usar la skill **`ship-interactions`**
> (`.claude/skills/ship-interactions/SKILL.md`): mapa, reglas de seguridad/a11y y depuración.

## Estructura

| Carpeta | Componentes |
|---------|-------------|
| `ship/` | `DeployWidget` (pipeline real con log y tiempo medido), `ConfigEditor` (portfolio.config.ts en vivo), `StackPlayground` (matter-js) |
| `ui/` | `Section` (etiqueta mono + título + intro), `ButtonLink` (primary/secondary, radio de la config), `icons.tsx` |
| `layout/` | `IntroScreen` (hello, world → Welcome), `ScrollChoreography` (revelados + Lenis), `SiteHeader` (punto verde + nombre, secciones, CV), `SiteFooter` (barra de estado del build) |
| `sections/` | `Hero`, `Config`, `Projects`, `Experience`, `Stack`, `About`, `Contact` + `ContactForm` (client) |

## Recorrido

| Sección | Etiqueta (`SECTION_LABELS`) | Qué es |
|---------|-----------------------------|--------|
| Hero `#top` | — | nombre, rol, intro, CTAs, highlights + **Deploy**: corre solo una vez (después de la bienvenida) y se puede redeployar |
| Config `#config` | portfolio.config.ts | "Make it yours.": editor en vivo + presets (Dark mode, Mono font, Sharp corners, Random accent) |
| Projects `#projects` | Deployments | dashboard tipo Vercel: preview, estado Ready/Building, dominio, stack, Live site / Code |
| Experience `#experience` | CHANGELOG.md | una "release" por empresa: roles como tags, logros como entradas "Added" |
| Stack `#stack` | node_modules | caja con física (todas las tecnologías) + lista agrupada con logos (el contenido real) |
| About `#about` | README.md | foto, bio, facts en grilla, educación, certificaciones |
| Contact `#contact` | Issues | canales + formulario "New issue" (label: opportunity) |

## Movimiento

- `ScrollChoreography` solo hace lo tranquilo: `[data-rise]` (titulares) y `[data-reveal]` (bloques), más Lenis en desktop.
- Los momentos fuertes son **interactivos** (deploy, config, física), no secuestran el scroll.

## Contratos

- ids de la nav = `NAV_ITEMS`; Hero es `#top`, main `#main`; `#config` fuera de la nav.
- Test ids: `deploy`, `stack-playground`, `intro`, `build-info`. El editor se busca por su `aria-label` ("portfolio.config.ts …").
- Hay dos `role="status"` en la página (deploy y formulario): los tests los buscan dentro de su sección.
- Links externos: `target="_blank" rel="noopener noreferrer"` (+ `sr-only` "opens in a new tab" en proyectos).

## Accesibilidad (axe en CI, con y sin reduced motion, después de recorrer la página)

- Un solo h1.
- Log del deploy y caja de física `aria-hidden`; el estado final se anuncia en un único `role="status"`.
- Editor: textarea real con `aria-label`; Problems en `aria-live="polite"`.
- Los títulos de experiencia tienen "##" decorativo `aria-hidden`.

## Rendimiento

- Sin video ni 3D.
- matter-js (~80 KB) se importa solo cuando la caja del stack entra en pantalla y con movimiento permitido.
- GSAP y Lenis son chunks dinámicos.
- Imágenes con `next/image`.

## Recorrido (`app/data/pipeline.ts` → `STAGES`)

| Comando | Sección | Salida | Etapa |
|---------|---------|--------|-------|
| `neofetch` | `#top` | logo ASCII, nombre (h1), rol, filas Host/Uptime/Packages/Projects/Certs/Status (calculadas), intro, CTAs, highlights y **la shell** | checkout |
| `cat stack.yaml` | `#stack` | grupos como claves YAML con chips; `./stack --gravity` con la caja de física | install |
| `ls -l ~/projects` | `#projects` | listado (cada entrada salta a su README) + cada proyecto como ventana `README.md` | build |
| `git log --author=…` | `#experience` | cada empresa es un commit (hash decorativo `shortHash`), logros como `+`, etiquetas detectadas; `ls ~/certs` | test |
| `cat about.md` | `#about` | foto (`avatar.jpg`), bio, facts como `clave: valor`, educación | release |
| `make deploy` | `#contact` | `DeployRun` (una línea por etapa, verde al pasarla; deploy "waiting for your approval"), canales, formulario | deploy |

## La shell (`terminal/Shell` + `lib/shell.ts`)

- `runCommand(línea, contenido, historial)` es puro y devuelve `{lines, action?}`. Las acciones son `scroll`
  (vía un `<a href="#id">` para que Lenis y el hash apliquen), `open`, `download` y `clear`.
- Comandos: `help`, `ls`, `cat`, `cd`, `open`, `whoami`, `neofetch`, `git log`, `contact`, `cv`, `github`,
  `linkedin`, `make deploy`, `history`, `clear`, más easter eggs (`sudo`, `rm`, `exit`, `vim`).
- Teclas:
  - Tab completa (`complete`).
  - ↑/↓ recorren el historial.
  - Ctrl+L limpia.
  - `/` enfoca la shell desde cualquier lado.
- Salida en `role="log"` `aria-live="polite"` con `data-lenis-prevent`. Input con label `sr-only`.

## Contratos

- `NAV_ITEMS` = stack, projects, experience, about, contact. La nav ("Sections") es la `StatusBar` de abajo e
  incluye `0:~` (top). La ventana actual lleva `aria-current="location"` y `*`, y en móvil se desplaza a la vista.
- Secciones con `data-stage` (las pone `<Command>`). Test ids:
  - `prompt-<id>`, `pipeline-status`, `deploy-run`, `shell`;
  - `stack-playground`, `intro`, `build-info`.
- `<wbr>` entre prompt y comando: los comandos largos bajan de línea en móvil (sin overflow).

## Accesibilidad (axe con y sin reduced motion, después de recorrer la página)

- Un solo h1 (el nombre en neofetch).
- Prompts, logo, swatches, hashes y `DeployRun` son `aria-hidden`.
- El `:` de las claves YAML es `aria-hidden` (los headings se llaman como el grupo).

## Rendimiento

Un solo listener de scroll pasivo (rAF) para todo el estado. matter-js se carga solo al ver la caja. GSAP y Lenis
son chunks dinámicos. Una sola fuente. Sin video ni 3D.

# 03 — UI (`ui`)

**Archivos:** `app/components/**`, `app/lib/site.ts`

## Estructura

| Carpeta | Componentes |
|---------|-------------|
| `ui/` | `PageHeader` (única h1 de páginas internas), `Block` (sección titulada: label a la izquierda en desktop, línea fina arriba), `TextLink` (link interno con →), `ExternalLink` (↗, nueva pestaña), `Tag` (punto de color + texto), `icons.tsx` |
| `layout/` | `SiteHeader`, `NavLinks` (client, `aria-current` por ruta), `ThemeToggle` (client), `SiteFooter` (build info + link al CI) |
| `projects/` | `ProjectList` (filas enlazadas a `/projects/<slug>`), `ArchitectureDiagram` (timeline vertical numerada), `RoadmapList` |
| `skills/` | `SkillLegend`, `SkillGroups` (un `Block` por categoría) |
| `about/` | `ExperienceList`, `EducationList` |
| `contact/` | `ContactDetails`, `ContactForm` (client) |

## Contratos

- **Rutas**: `NAV_ITEMS` en `lib/site.ts` es la única lista; `isActivePath` marca también rutas hijas (`/projects/x` → Work).
- **URLs de proyecto**: siempre `projectHref(slug)`, nunca strings armados a mano.
- Links externos: `ExternalLink` (o `target="_blank" rel="noopener noreferrer"`); los tests lo validan en todas las páginas.
- Los componentes no importan datos salvo `profile` en piezas globales (header, footer, contacto); el resto recibe datos por props desde las páginas.

## Patrones de estilo

- Tokens de la capa 02; `label` para rótulos; `font-serif` para títulos de proyectos/roadmap.
- Listas separadas por `divide-y divide-border`, no tarjetas.
- Mobile: el header se apila (nombre arriba, nav + toggle abajo); `Block` pasa a una columna.

## Accesibilidad (verificada por axe en CI)

- Una sola h1 por página; `Block` = `<section aria-labelledby>`.
- Skip link a `#main`; foco visible global; `aria-current="page"` en la nav.
- Formularios con `label htmlFor`, `aria-invalid`, `aria-describedby`, `role="alert"`/`"status"`.
- `ArchitectureDiagram` es un `<ol aria-label>`; la decoración es `aria-hidden`.

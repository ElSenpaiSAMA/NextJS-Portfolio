# 03 — UI (`ui`)

**Archivos:** `app/components/{layout,sections,ui}/**`, `app/lib/site.ts`

## Estructura

| Carpeta | Contenido |
|---------|-----------|
| `ui/` | Primitivas sin datos: `Section` (id + índice + h2 + intro), `Tag` (tonos neutral/accent/ok/warn/info), `ButtonLink`, `ExternalLink`, `icons.tsx` (SVG inline) |
| `layout/` | `SiteHeader` (nav por anclas, skip link, toggle), `SiteFooter` (build info), `ThemeToggle` (client) |
| `sections/` | Una por sección; leen de `app/data` y renderizan. `CaseStudy`/`ProjectCard` + `ArchitectureDiagram` para proyectos. `ContactForm` (client) |

## Contratos

- **ids de sección** = `NAV_ITEMS` en `lib/site.ts` (`SectionId`). `Section` exige un `SectionId`, así TypeScript impide ids sueltos.
- **ids de proyecto** = `slug` de cada proyecto; el Hero enlaza a `#spotify-pipeline` y `#portfolio` (un test de datos lo verifica).
- `#top` (hero) y `#main` (skip link) son anclas fijas.
- Links externos: siempre `ExternalLink` o `ButtonLink external` → `target="_blank" rel="noopener noreferrer"` (E2E y test de página lo validan).

## Patrones

- Server Components por defecto. Client solo con interacción real (`ThemeToggle`, `ContactForm`).
- Estilos: utilidades Tailwind con tokens (capa 02). Contenedor estándar `mx-auto max-w-5xl px-5`.
- Labels técnicos: `font-mono text-xs uppercase tracking-wider text-subtle`.
- `ArchitectureDiagram`: `<ol>` accesible; flechas `aria-hidden`; horizontal en `lg`, vertical en mobile; color por `kind`.
- Mobile: la nav se reduce a "Contact" + toggle (`md:` muestra todo).

## Accesibilidad (obligatoria, verificada por axe en CI)

- Un solo `h1`; cada sección `aria-labelledby` su `h2`.
- Skip link a `#main`; foco visible global.
- Formularios: `label htmlFor`, `aria-invalid`, `aria-describedby` al error, `role="alert"`/`role="status"`.
- Iconos decorativos `aria-hidden`; botones solo-icono con `aria-label`.

## Deuda técnica conocida

- `ArchitectureDiagram`: con `flex-wrap` en `lg` puede quedar una flecha al final de una fila.
